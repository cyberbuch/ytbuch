# Данни

Схемата се създава при старт на API-то (`CREATE TABLE IF NOT EXISTS`).
Няма индекси и няма външни ключове: Octo на този контейнер не ги дава.
Връзките (`company_id`, `invoice_id`, `entry_id`, `account_id`) са обикновени
`INTEGER` и ги пази приложението.

`schema_migrations`:

| id | name | Какво прави |
|----|------|-------------|
| 1 | `phase1_auth_companies` | отбелязва, че таблиците на първата фаза са пуснати |
| 2 | `demo_company` | демо фирмата и записите по-долу. Маркерът е накрая. Прекъснат seed пропуска вече записан `id` и довършва липсващите |
| 3 | `saft_accounts` | допълва липсващите номера от каталога на НАП. Съществуващ номер се пропуска |

`schema5`, `schema_late` и `fsform` пускат `CREATE TABLE IF NOT EXISTS` при
всеки старт. Нямат ред в `schema_migrations`. Номерата `1`, `2` и `3` са
само за първата фаза, демото и seed на сметкоплана.

Всяка стъпка с данни е повторяема. Таблиците се създават с
`CREATE TABLE IF NOT EXISTS`. Ред с данни се пише през `insert_missing`:
ако `id` вече съществува, се пропуска. Seed на сметкоплана пропуска по
номер, защото ключът е номерът, не поредното `id`. Активната фирма на
`superadmin` се търси по ключ `активна_фирма:superadmin`. Маркерът в
`schema_migrations` се пише след успешната стъпка. След маркера стъпката
не се пуска отново. Нова колона към стара таблица остава отделна таблица:
Octo тук няма `ALTER TABLE`.

Часовете и датите са `VARCHAR`. Сумите са `VARCHAR`, в JSON остават низ.
Пълният списък колони за бекъпа е в `backend/src/dump.rs`.

## Демо фирма

Миграция `2` обновява фирма `id = 1` на място и после добавя записите.
Ако фирма 1 я няма, първо я създава.

| | |
|--|--|
| Име | YT ООД |
| ЕИК / ДДС | `207123456` / `BG207123456`, регистрация по ДДС |
| Валута | EUR, период `monthly`, метод на запаси `WAC`, фискален месец 1 |
| Адрес | София 1000, бул. Витоша 1, област София |
| Телефон / поща | `02 000 0000`, `office@baga.example` |
| МОЛ и управител | Иван Петров |
| НАП | основа `A`, офис `ТД на НАП София` |
| Банка | IBAN `BG80BNBG96611020345678`, BIC `BNBGBGSD` |
| Активна за | `активна_фирма:superadmin` = `1` |

Обекти: **Офис Витоша** (`OFFICE`, основен) и **Склад Младост** (`WAREHOUSE`).
Собственик: Иван Петров, 100%. Крайна майка: YT Холдинг ЕАД, ЕИК `175000001`.
Серия **Фактури**, типове `01,02,03`, следващ номер `0000000003`.

Сметки от демото (преди каталога на НАП), всички с `company_id = 1`:

| Номер | Име в демото | `analytic_type` |
|-------|----------------|-----------------|
| 302 | Материали | none |
| 401 | Доставчици | counterpart |
| 411 | Клиенти | counterpart |
| 4531 | Начислен ДДС | none |
| 501 | Каса в лева | none |
| 601 | Разходи за материали | none |
| 702 | Приходи от продажби | none |

Seed на каталога пропуска номер, който вече съществува, и пази това име.
Номер, който го няма в каталога, остава допълнителен ред. На този volume
след seed има **361** сметки: 360 от каталога и един демо номер извън него.
Първата по номер е `101 Основен капитал, изискващ регистрация`.

Контрагенти: **Клиент Демо ЕООД** (`customer`, Пловдив) и **Доставчик Демо ООД**
(`supplier`, Варна). Стока: **Консултация** `SRV-1`, цена `100.00`, ДДС `20`,
услуга, приходна сметка id 7.

Фактури:

| Номер | Посока | Дата | Контрагент | Нето / ДДС / общо | Статус |
|-------|--------|------|------------|-------------------|--------|
| `0000000001` | out | 2026-10-01 | Клиент Демо ЕООД | 1000.00 / 200.00 / 1200.00 EUR | posted |
| `0000000042` | in | 2026-10-02 | Доставчик Демо ООД | 250.00 / 50.00 / 300.00 EUR | draft |

Редове: консултация 10 × 100.00 (`HUR`) и канцеларски материали `MAT-1` (`C62`).

Дневник към тях:

- Продажба: Дт 411 `1200.00`, Кт 702 `1000.00`, Кт 4531 `200.00`
- Покупка: Дт 601 `250.00`, Дт 4531 `50.00`, Кт 401 `300.00`

Тези редове идват от seed-а. Нов пост на продажба слага приходната сметка на артикула и ДДС по кредита на `4532`. Нов пост на покупка слага складовата или разходната сметка на артикула и ДДС по дебита на `4531`. Себестойност във фактурата няма: тя е месечен запис по правилата в настройки, таб Склад. Правилата не се сеят.

Таблото на тази база: 1 публикувана, 1 чернова, вземания `1200.00`,
задължения `300.00`, `bank_total` `0.00`.

Демо данните са за локална проверка. Паролата `123+123` и JWT тайната по
подразбиране се сменят преди машината да е достъпна извън този компютър.
