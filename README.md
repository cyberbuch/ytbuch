# ytbuch — счетоводна програма

Същата счетоводна програма като bagabuch, на друг стек: Rust и Axum, YottaDB
с Octo, и копираният Next.js интерфейс.

**Документация (текущо състояние на кода):** [`docs/`](docs/README.md) —
архитектура, API, данни, SAF-T номенклатури и какво още липсва.
`PLAN.md` е пътната карта на миграцията. `start-ytbuch.md` е първоначалната бележка.

Базовата валута е **евро (EUR)**. Черното сторно остава правилото: отрицателен
знак, без обръщане на дебит и кредит. Сумите в JSON са низове.
`company_id` дели данните по фирма.

## Стек

| Слой | Технология |
|------|------------|
| Backend | Rust + Axum 0.8, JWT HS256 |
| База | YottaDB r2.06, SQL през Octo 1.1.0 |
| Frontend | Next.js 16 (App Router), същите екрани като bagabuch |
| Автентикация | `POST /v1/auth/token`, SHA-256 на `bagabuch\|{email}\|{парола}` |
| Поща и архив | `lettre` и `aws-sdk-s3` в API процеса. Няма Python контейнер |

## Портове

| Услуга | Адрес |
|--------|--------|
| Octo (SQL) | `127.0.0.1:1337` |
| YottaDB GUI | http://127.0.0.1:9080 |
| API | http://127.0.0.1:8092 |
| Интерфейс | http://127.0.0.1:3020 |

Портовете `3000` и `3010` са на bagabuch и 7x7office. ytbuch не ги ползва.
SQL и GUI слушат само на `127.0.0.1`.

Образ: `download.yottadb.com/yottadb/yottadb-debian:latest`.
Контейнер: `ytbuch-yottadb`. Данните са във volume `ytbuch_ydb-data` (`/data`).
Потребител `ydb`, парола `ydbrocks`.

## Какво работи сега

- Вход, `/v1/me`, фирми (създаване, преглед, частичен PATCH, изтриване), активна фирма, табло.
- Настройки на фирмата: обекти, действителни собственици, крайни майки и серии — четене и запис.
- Сметкоплан: списък, seed от НАП, създаване и редакция на отделна сметка. Повторният seed не дублира номера.
- SAF-T номенклатури: 11 вида, статичен каталог (сметки 360, мерни единици 127, данъчни кодове 169 и останалите). Мерните единици са и на `GET /v1/units`.
- Контрагенти и стоки: четене и запис.
- Фактури: чернова, следващ номер, пост, черно сторно, печат PDF/DOCX/ODT и UBL. Дневникът се чете.
- ДДС дневници и файл за НАП, периоди и начални салда. Затворен месец спира поста.
- Банки (CSV и MT940), ДМА, склад, протоколи с печат, производство и дивиденти. XML извлечения остават.
- Админ: глобални настройки, SMTP тест и S3 бекъп. Архивът е `ytbuch_backup_*.sql.gz`.
- Моят профил: парола, имейл и 2FA с QR и файл с резервни кодове.
- Демо фирма **Бага ООД** (ЕИК `207123456`) с две фактури и два записа в дневника.

Копираните екрани, за които още няма запис в API-то, при GET получават празен
списък. Записът им връща `404`. Пълният списък е в [`docs/status.md`](docs/status.md).

## Стартиране

От корена на baga:

```bash
docker compose -f app-product/ytbuch/deploy/docker-compose.yml up -d
cd app-product/ytbuch/backend && cargo run
cd app-product/ytbuch/frontend && npm install && npm run dev
```

Отвори http://127.0.0.1:3020. Вход: **`superadmin` / `123+123`**.

При първи старт API-то създава таблиците, демо фирмата и липсващите сметки
от каталога на НАП. Готовност: `GET /ready` връща `{"status":"ok","database":"up"}`.

## Променливи

| Променлива | По подразбиране |
|------------|-----------------|
| `YTBUCH_PORT` | `8092` |
| `YTBUCH_DATABASE_URL` | `host=127.0.0.1 port=1337 user=ydb password=ydbrocks dbname=ydb sslmode=disable` |
| `YTBUCH_JWT_SECRET` | `ytbuch-local-jwt-secret-change-me` |
| `YTBUCH_API_PROXY` | `http://127.0.0.1:8092` (Next препраща `/v1`, `/health`, `/ready`) |

## Изисквания

- Docker, за контейнера с YottaDB и Octo
- Rust (проектът е на edition 2021; локално е проверяван с 1.97)
- Node ≥ 20 за Next.js
