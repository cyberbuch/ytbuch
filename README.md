# ytbuch — счетоводна програма

**Серия Baraba · модел ytbuch** — счетоводна програма с отворен код:
Rust и Axum, YottaDB с Octo и Next.js интерфейс.

**Документация (текущо състояние на кода):** [`docs/`](docs/README.md) —
[архитектура](docs/architecture.md) (модули и потоци), API, данни, SAF-T номенклатури и какво още липсва.
`PLAN.md` е пътната карта. `start-ytbuch.md` е първоначалната бележка.

Базовата валута е **евро (EUR)**. Черното сторно остава правилото: отрицателен
знак, без обръщане на дебит и кредит. Сумите в JSON са низове.
`company_id` дели данните по фирма.

## Стек

| Слой | Технология |
|------|------------|
| Backend | Rust + Axum 0.8, JWT HS256 |
| База | YottaDB r2.06, SQL през Octo 1.1.0 |
| Frontend | Next.js 16 (App Router) |
| Автентикация | `POST /v1/auth/token`, argon2id (наследени sha256 хешове се мигрират при вход), JWT HS256 |
| Поща и архив | `lettre` и `aws-sdk-s3` в API процеса. Няма Python контейнер |

## Портове

| Услуга | Адрес |
|--------|--------|
| Octo (SQL) | `127.0.0.1:1337` |
| YottaDB GUI | http://127.0.0.1:9080 |
| API | http://127.0.0.1:8092 |
| Интерфейс | http://127.0.0.1:3020 |

ytbuch не заема портове `3000` и `3010`.
SQL и GUI слушат само на `127.0.0.1`.

Compose стартира `ytbuch-yottadb`, `ytbuch-backend` и `ytbuch-frontend` с
`restart: unless-stopped`. Данните са във volume `ytbuch_ydb-data` (`/data`).
Потребителят на Octo е `ydb`, паролата е `ydbrocks`.

## Какво работи сега

- Вход, `/v1/me`, фирми (създаване, преглед, частичен PATCH, изтриване), активна фирма, табло.
- Настройки на фирмата: обекти, действителни собственици, крайни майки и серии — четене и запис.
- Сметкоплан: списък, seed от НАП, създаване и редакция на отделна сметка. Повторният seed не дублира номера.
- SAF-T номенклатури: 12 вида, статичен каталог (сметки 360, мерни единици 127, данъчни кодове 169, КН8 и останалите). Мерните единици са и на `GET /v1/units`.
- SAF-T XML: `GET /v1/saft/export` за месец, година и при поискване. Схемата е V1.0.1. Месец без банково плащане не минава XSD.
- Контрагенти и стоки: четене и запис. Дубликат по ЕИК/ДДС номер не се допуска (ЕИК `999999999` е за еднократни контрагенти).
  Стоките имат вид запас, КН8 класификация (каталог и AI предложение), авто-код и опция за автоматично изписване при покупка.
- Фактури: чернова, следващ номер, пост, черно сторно, печат PDF/DOCX/ODT и UBL. Дневникът се чете.
  Входящи фактури могат да са извън ДДС дневник; ДДС се отразява с протокол по чл. 117 ЗДДС или митническа декларация (кредит 458).
- ДДС дневници и файл за НАП, периоди и начални салда. Затворен месец спира поста.
- Банки (CSV, MT940 и XML — Postbank, UniCredit, OBB, camt.053), ДМА, склад по настройки (преизчисляване, месечно изписване, ръчни материали и справка), протоколи с печат, производство и дивиденти.
- Админ: глобални настройки, SMTP тест и S3 бекъп. Архивът е `ytbuch_backup_*.sql.gz`.
- Моят профил: парола, имейл и 2FA с QR и файл с резервни кодове.
- Публична регистрация с нова фирма и забравена парола. Писмото тръгва при зададени SMTP и `app.url`.
- Потребители и роли, курсове на ЕЦБ, VIES, разбиване на адрес, съпоставяне на SAF-T движения.
- Одитна следа с потребител и timestamp за документите и счетоводните статии. Ръчните записи в дневника се трият и групово.
- Списъчните екрани странират по 50 реда с търсене измежду всички редове.
- UBL вход и сканиране към чернова. Сканирането иска Mistral ключ. Имената на стоки се запомнят.
- Демо фирма **YT ООД** (ЕИК `207123456`) с две фактури и два записа в дневника.

Пълният списък е в [`docs/status.md`](docs/status.md).

Потребителското ръководство с екрани и стъпки е в [`user-docs/`](user-docs/README.md).

## Стартиране

От корена на проекта:

```bash
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml ps
```

Трите контейнера се стартират автоматично след рестарт на Docker. Отвори
http://127.0.0.1:3020. Вход: **`superadmin` / `123+123`**.

При първи старт API-то създава таблиците, демо фирмата и липсващите сметки
от каталога на НАП. Готовност: `GET /ready` връща `{"status":"ok","database":"up"}`.

## Променливи

| Променлива | По подразбиране |
|------------|-----------------|
| `YTBUCH_HOST` | `127.0.0.1` (`0.0.0.0` в контейнера) |
| `YTBUCH_PORT` | `8092` |
| `YTBUCH_DATABASE_URL` | `host=127.0.0.1 port=1337 user=ydb password=ydbrocks dbname=ydb sslmode=disable` |
| `YTBUCH_DATABASE_POOL_SIZE` | `8` |
| `YTBUCH_JWT_SECRET` | няма — API-то генерира случайна тайна при първия старт и я пази в базата |
| `YTBUCH_API_PROXY` | `http://127.0.0.1:8092` (Next препраща `/v1`, `/health`, `/ready`) |

## Изисквания

- Docker с Compose за постоянния стек
- Rust (edition 2021, проверен с 1.97) само за локална разработка без контейнер
- Node ≥ 20 само за локална разработка без контейнер
